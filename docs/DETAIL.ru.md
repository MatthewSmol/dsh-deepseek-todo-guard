# Сторож TODO — устройство и ограничения

[English](DETAIL.md) · **Русский**

## Почему плагин ничего не рисует сам

Плашка «Задачи» — штатная часть DSH (`@deepseek-ai/dsh-client-ui-conversation`,
слот `conversation.input.dock`, id `todo`). Она стоит над полем ввода, свёрнута
по умолчанию, показывает задачи текущего раунда и читает проекцию `todos`.
Проекцию наполняет событие `todo/write`, которое обычно пишет инструмент
`todo_write` агента. Пока список пуст, панель не рендерится, а на `turn/start`
проекция обнуляется — между ходами плашки нет, пока список не запишут снова.

Поэтому плагин не создаёт свою панель: он следит, чтобы событие `todo/write`
появлялось вовремя. Вторая панель только дублировала бы штатную.

## Проверка раз в 30 секунд

Единый таймер обходит живых агентов (`ctx.agents` — это `AgentRegistry` с
`list()`, итератора у него нет) и читает лог каждой сессии: номер хода, был ли
`todo/write` в этом ходе, когда он был, тексты человека и ассистента, имена
инструментов, открыт ли ход.

| Ситуация | Действие | Причина в журнале |
|---|---|---|
| в ходе нет `todo/write`, списка нет | создать | `в этом ходе списка нет` |
| в ходе нет `todo/write`, список от прошлого хода | заменить | `список относится к прошлому ходу` |
| ход закрылся, есть незавершённые | отметить выполненными | `ход завершён, есть незавершённые` |
| идёт ход, и список старше `refreshSeconds` | обновить | `список обновляется по ходу работы` |
| агент простаивает, список старше `staleAfterMinutes` | обновить | `список давно не обновлялся` |
| список свеж | не трогать | `список актуален` |

`turn/end` обрабатывается сразу, без ожидания тика, чтобы галочки появлялись без
задержки в 30 секунд.

## Журнал в сайдбаре

Каждая подсказка записывается: время, id сессии и её название (из
`session/title`), действие (`create`/`refresh`/`promote`), источник формулировок
(`model`/`heuristic`/`none`) и число задач. Последние 50 записей живут в памяти и
в файле `.nudges.json` рядом с пакетом, поэтому история переживает перезапуск.

Панель — клиентская половина плагина:

- пункт `sidebar.panellist` с id `todo-watch-log`, порядок 45, иконка-чеклист с
  часами;
- панель `main` с тем же ключом: заголовок, строка «последние N · обновлено …»,
  карточки записей (время, сессия, действие, источник, число задач, причина);
- опрос `GET /todo-watch/nudges` каждые 5 секунд.

Маршрут регистрируется в хост-сервисе `webServer` и защищён одноразовым токеном
процесса: хост подставляет в HTML страницы глобал
`__TODO_WATCH__ = { endpoint, token, historySize }` через событие
`webserver/index-inject`, а панель отправляет токен заголовком
`x-todo-watch-token`. Ответы идут с `cache-control: no-store`, POST даёт 405.
После перезапуска `dsh web` токен меняется, поэтому старую вкладку нужно
обновить — иначе панель покажет «Нет связи со сторожем».

## Откуда берутся формулировки

### Модель сессии (по умолчанию)

Одноразовый вызов `ctx.llm` тем же маршрутом, что и основной запрос сессии
(`session.requestHeader().config`), с ограничениями:

- не чаще одного вызова на сессию (`llmMinIntervalSeconds`, по умолчанию 60 с);
- один вызов в полёте на сессию; при выгрузке агента вызов отменяется;
- таймаут (`llmTimeoutMs`, 20 с) и лимит токенов (`llmMaxOutputTokens`, 400);
- вход — компактный JSON: запрос человека, последние ответы ассистента, имена
  инструментов и текущий список (несколько КБ).

Модель возвращает строго
`{"todos":[{"content":"…","status":"pending|in_progress|completed"}]}`. Ответ
нормализуется: строки обрезаются до 120 символов, не больше `maxItems`, без
повторов, допустимые статусы, не больше одной задачи «в работе», если
параллелизм запрещён. Мусор и таймауты отбрасываются — лучше оставить прежний
список, чем показать выдуманный.

### Эвристика

Если модель недоступна, не настроена (`curator: heuristic`), не ответила вовремя
или ответила мусором:

- существующий список сохраняет формулировки и двигает только статусы: при
  закрытом ходе всё становится `completed`, при открытом первая незавершённая
  задача становится `in_progress`;
- если списка нет, пункты берутся из запроса человека (нумерованные и
  маркированные строки, иначе строка целиком), первый помечается «в работе»;
- пустой запрос даёт одну общую задачу, чтобы плашка не была пустой.

## Запись в лог

`session.append('todo/write', { todos })` — только когда список реально
изменился. Ошибки записи логируются и не повторяются на следующем тике. Событие
не будит агента и не попадает в его контекст модели: это log-only состояние
интерфейса.

## Настройки

```yaml
- id: todo-watch
  config:
    checkIntervalSeconds: 30
    refreshSeconds: 60
    staleAfterMinutes: 10
    curator: llm
    llmProvider: ''            # по умолчанию маршрут сессии
    llmModel: ''
    llmMinIntervalSeconds: 60
    llmTimeoutMs: 20000
    llmMaxOutputTokens: 400
    maxItems: 7
    allowParallelInProgress: true
    promoteCompletedOnTurnEnd: true
    includeSubagents: false
    historySize: 5             # записей в панели сайдбара (1–50)
```

## Одно состояние на процесс

Журнал, токен страницы и отметка о маршруте живут в модуле, а не внутри `apply`.
Cordis может перезагрузить строку плагина без перезапуска сервера, и новый
`apply` иначе создал бы второй пустой журнал за тем же маршрутом: панель
показывала бы 0 записей, пока сторож продолжает писать в файл. Состояние общее
для всех активаций, маршрут регистрируется один раз, а подпись последней записи
по сессии отсекает дубли `todo/write` от двух таймеров.

## Проверка, что новая версия загружена

При каждом тике сторож пишет рядом с пакетом `.watch-alive.json`:

```json
{ "at": "2026-11-24T05:23:40.689Z", "version": 2, "note": "тик",
  "intervalMs": 30000, "curator": "llm", "agents": 4, "nudges": 3, "projection": "ok" }
```

Если файла нет или в нём старая дата — работает предыдущий модуль: Node кэширует
ESM, поэтому смена кода требует перезапуска `dsh web`. Поле `agents` показывает,
сколько живых агентов обошёл последний тик, `nudges` — размер журнала, а
`projection` — итог последней сверки: `ok` значит, что проекция `todos` штатной
плашки содержит только что записанный список, `missing` — что она его не увидела,
`pending` — записей ещё не было.

## Ограничения

- Плашка существует только у пресетов, где объявлена проекция `todos`
  (`standard`, `ptc`, `cordis`). В `minimal` плагин молчит.
- Плагин работает с живыми сессиями: закрытая сессия обслуживается, когда её
  снова откроют.
- Вызовы модели расходуют токены; частоту ограничивает `llmMinIntervalSeconds`,
  полностью отключает `curator: heuristic`.
- Правка bundle-патча применяется после перезапуска `dsh web`.
