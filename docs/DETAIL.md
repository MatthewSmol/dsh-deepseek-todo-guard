# Сторож TODO

Плагин DeepSeek Harness, который следит, чтобы у сессии был актуальный список
задач, и подсказывает агенту обновить его.

## Пункт сайдбара и панель

На левом сайдбаре появляется пункт **«Сторож TODO»** (иконка чеклиста с
часами). Он открывает главную панель:

- задачи текущей сессии с тремя состояниями (ожидает / в работе / выполнено) и
  индикатором прогресса;
- итог последней проверки: когда, почему сработала подсказка, сколько подсказок
  отправлено;
- параметры сторожа: интервал проверки и порог устаревания.

Панель читает штатную проекцию `todos` (`@deepseek-ai/dsh-tool-todo`) и
собственную проекцию `todo-watch/last-check`, которую собирает сторож из
событий лога.

## Проверка раз в 30 секунд

Один таймер на весь Host обходит живые агенты. Правила — чистые функции в
`src/watch/watcher.ts`:

| Причина | Условие | Что видит агент |
|---|---|---|
| `stale` | список не обновлялся дольше порога, агент простаивает | «Список задач TODO не обновлялся больше N мин…» |
| `all-completed` | все задачи `completed`, а в inbox ждёт работа | «Все задачи отмечены выполненными, но в сессии ждёт работа…» |
| `no-todo` | идёт новый ход, а `todo_write` в нём ещё не вызывали | «Новый ход начался без записи списка TODO…» |

Подсказка — сообщение с источником `todo-watch` и формой `notice`: оно
попадает в контекст следующего шага, но не будит простаивающую сессию. За ход
на каждую причину — не больше одного напоминания. Каждая проверка дописывает
`todo-watch/check` (время, ход, причина, отправлена ли подсказка, счётчики),
поэтому журнал виден в панели.

## Почему две строки патча

DSH принимает запись события только если его тип объявлен в дополняемом
словаре `SessionEventMap`, а объявления собираются из загруженных модулей. У
чужих плагинов (`@deepseek-ai/dsh-tool-todo`) `todo-watch/check` не объявлен,
поэтому пакет заменяет строку `todo-write` в пресетах своей: штатный
инструмент `todo_write` с тем же поведением и описанием, а его модуль
объявляет и `todo/write`, и `todo-watch/check`. Вторая строка — `todo-watch` —
собственно сторож (`@local/dsh-todo-watch/host`).

По той же причине патч заменяет строку `preset-standard` целиком: конфигурация
пресета повторяет штатную и сохраняет его состав. После установки плагина
пресет `standard` принадлежит патчу этого пакета — при редактировании его в
интерфейсе DSH изменения будут перекрыты патчем.

## Почему без Rust

Вся работа — таймер, чтение лога сессии и запись события через API
Host-плагина на Node. Нативный модуль не ускорил бы ничего (тик — десятки
микросекунд), но добавил бы тулчейн и сборку на каждую платформу. Клиентская
половина живёт в браузере, поэтому собирается TypeScript + Vite; Host —
TypeScript с минификацией terser.

## Сборка и оптимизация

```bash
npm install
npm run typecheck     # tsc: хост и клиент
npm run build:host    # tsc → dist
npm run build:host:min # terser: сжатие и имена
npm run build         # полная сборка с проверками
npm test              # typecheck + node --test
```

- Клиент: IIFE без зависимостей, React из таблицы модулей DSH, CSS встроен
  строкой и минифицирован, source maps отключены, лимит 250 КБ; при сборке
  печатаются размеры gzip/brotli.
- Host: `tsc` в `dist/`, затем terser с двумя проходами сжатия; лимиты —
  60 КБ для `dist/index.js` и 20 КБ для модулей `watch/`.
- `scripts/check-events.mjs` проверяет, что объявления событий попали в
  собранный код; без них сторож не сможет писать в лог.
- `scripts/fix-imports.mjs` дописывает `.js` в относительные импорты
  собранного Host-кода (требование ESM).

## Ограничения

- Следит за живыми сессиями верхнего уровня, у которых есть список TODO;
  сессии без списка не трогает.
- Если пресет агента не содержит `todo_write`, подсказки не отправляются.
- Подсказка простаивающему агенту лежит в inbox до следующего сообщения —
  это штатное поведение `agent.inject()`.
